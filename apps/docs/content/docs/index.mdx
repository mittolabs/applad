Applad gives your app every backend service it needs — **databases, authentication,
storage, functions, messaging, realtime and workflows** — behind one consistent REST API
and admin console, running from a single `docker compose up`.

## Why Applad

- **Self-hosted.** It runs on your infrastructure. No vendor lock-in, no per-seat pricing.
- **Batteries included.** Postgres, Redis, the API, background workers and the console all
  ship together.
- **One API.** Every service is reachable under `/v1` with the same auth model, and there
  are SDKs for JavaScript, Node, Dart, Go and Python.

## Where things live

| Surface | URL |
| --- | --- |
| Marketing site | `applad.io` |
| Admin console | `console.applad.io` |
| API (what your SDKs talk to) | `api.applad.io` |
| These docs | `docs.applad.io` |
| Your deployed apps | `<app>.applad.dev` |

<Callout title="Why two domains">
  Everything of ours lives on `applad.io`; deployed apps get `applad.dev` to
  themselves. Since deployed apps run your code, keeping them on a separate
  registrable domain means one app can never set cookies the console would
  read, or count as same-site with it.
</Callout>

<Callout title="Local development">
  Locally the same hosts are used with a `.localhost` suffix (e.g.
  `console.applad.io.localhost`), which every Chromium browser resolves to
  `127.0.0.1` automatically.
</Callout>
