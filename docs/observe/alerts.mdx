---
title: Alert rules
description: Define threshold rules over a metric with a notification channel, and list any open incidents.
---

Define a rule over a metric with a threshold and a notification channel:

```dart
await client.observe.createAlertRule(
  'High error rate',
  metric: 'error_rate',
  operator: 'gt',
  threshold: 5,
  window: '5m',
  severity: 'warning',
  channel: 'email',
);
```

List rules and any open incidents:

```bash
curl "$APPLAD/v1/observe/alerts" \
  -H "x-applad-project: $PROJECT" -H "x-applad-key: $KEY"
```

Rules can be toggled and deleted. See Alert rules.

<Callout title="Rules are stored; evaluation is not automated yet">
You can create, list, toggle, and delete alert rules, and the alerts response
returns any open incidents. This build has no server-side evaluator that
watches metrics and fires those incidents, so rules are configuration that
nothing acts on automatically yet. Use them together with uptime checks and
error triage rather than as a paging system.
</Callout>
