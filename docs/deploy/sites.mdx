Applad can build your app from source and run it for you. You describe **what**
to run as a deploy target, give it the code, and Applad builds an image, starts
a container, and serves it at `<name>.applad.dev` with a certificate issued
automatically. A target can be a web app, a serverless function, or a
long-running container.

Everything on this page lives under `/v1/deploy` and needs the project header
plus a key. Deploy management is a server-side task, so the examples use an API
key (`x-applad-key`). Set these once:

```bash
export APPLAD=https://api.applad.io
export PROJECT=<projectId>
export KEY=<apiKey>
```

<Callout title="Client SDK coverage">
The Dart client SDK's `deploy` helper currently wraps only a minimal surface and
does not cover targets, pipelines, or releases. Manage deployments from the
console or the REST routes shown here.
</Callout>

## Deploy targets

A **target** is the thing you deploy. It has a `type`:

| Type | What it is | Address |
|---|---|---|
| `web` | An app served over HTTP (static site or a server) | `<name>.applad.dev` |
| `serverless` | A function you invoke on demand | none (invoked via the API) |
| `container` | A long-running container from a registry image | assigned per target |

`web` is the default if you omit `type`. Mobile and desktop targets are surfaced
in the console's navigation but are not built by this API; only `web`,
`serverless`, and `container` are handled by the deploy engine.

### Create a target

```bash
curl -X POST "$APPLAD/v1/deploy/targets" \
  -H "x-applad-project: $PROJECT" -H "x-applad-key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "The Range", "type": "web"}'
```

For a `web` target, Applad derives a **subdomain** from the name and claims it at
creation time: `"The Range"` becomes `the-range`, served at
`https://the-range.applad.dev`. The response includes the derived `subdomain`
and the full `url`:

```json
{
  "$id": "6f2c...",
  "name": "The Range",
  "type": "web",
  "subdomain": "the-range",
  "url": "https://the-range.applad.dev"
}
```

A subdomain is global across every project, so two sites cannot claim the same
one. If the name reduces to a subdomain another site already answers on, the
create returns `409 Conflict` and you pick a different name. This is deliberate:
a silently different address is a worse surprise than being told.

Optional fields on create: `runtime` and `entrypoint` (serverless),
`timeoutMs` (default `30000`), `memoryMb` (default `256`), `envVars`
(a string map), `permissions`, and `cron` (a schedule; validated when written,
so a bad expression is rejected at the API).

List, fetch, update, and delete targets:

```bash
curl "$APPLAD/v1/deploy/targets"            -H "x-applad-project: $PROJECT" -H "x-applad-key: $KEY"
curl "$APPLAD/v1/deploy/targets/$TARGET"    -H "x-applad-project: $PROJECT" -H "x-applad-key: $KEY"
curl -X DELETE "$APPLAD/v1/deploy/targets/$TARGET" -H "x-applad-project: $PROJECT" -H "x-applad-key: $KEY"
```
