---
title: "Flaky and quarantine"
description: "A test that failed then passed within a run is recorded as flaky, and a quarantined test still runs but no longer decides the verdict."
---

Retries are honoured. When a runner retries a test, the report lists each
attempt; Applad collapses them to one result, where the last attempt is the
outcome. A test that **failed and then passed within the same run** is recorded
as `flaky` rather than failing the run. The `flaky` count on a run and the
`flaky` flag on a history entry make "sometimes red" a fact instead of an
argument.

A **quarantined** test still runs and still reports, but no longer decides the
verdict. This is how a known-flaky test stops blocking deploys without being
deleted and forgotten. A quarantined failure shows up in the run's `quarantined`
count instead of its `failed` count.

```bash
curl -X PUT https://api.applad.io/v1/tests/<testId>/quarantine \
  -H "x-applad-key: <apiKey>" \
  -H "Content-Type: application/json" \
  -d '{ "quarantined": true }'
```
