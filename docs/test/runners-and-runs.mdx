title: "From runner to run"
description: "Describe how your tests run, give the worker your source, emit a JUnit report, then trigger a run and read the verdict."
---

The path from nothing to a verdict is a handful of steps: describe how your
tests run, give the worker your source, emit a JUnit report, then trigger a run
and read the verdict.

<Steps>

<Step>
## Create a runner

A runner says how your tests run. `name` and `command` are required; everything
else has a sensible default.

```bash
curl -X POST https://api.applad.io/v1/tests/runners \
  -H "x-applad-key: <apiKey>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "API tests",
    "sourceType": "git",
    "sourceUrl": "https://github.com/acme/app.git",
    "branch": "main",
    "image": "node:20",
    "setupCmd": "npm ci",
    "command": "npm test",
    "reportPath": "junit.xml",
    "artifactsPath": "test-results",
    "envVars": { "CI": "true" },
    "timeoutMs": 900000
  }'
```

| Field | Meaning |
| --- | --- |
| `name` | Required. Display name. |
| `sourceType` | `git` or `upload` (default `upload`). `generated` is reserved for recorded flows. |
| `sourceUrl`, `branch` | Repository and branch, when `sourceType` is `git`. |
| `image` | Base image the tests run in. |
| `setupCmd` | Shell command run before the tests (install dependencies, build). |
| `command` | Required. The shell command that runs the suite. |
| `reportPath` | Where the suite writes its JUnit XML. Defaults to `junit.xml`. |
| `artifactsPath` | A directory the suite writes recordings and screenshots into. Empty means none. |
| `envVars` | Environment variables passed into the container. |
| `timeoutMs` | Run timeout. Defaults to `900000` (15 minutes). |

The response is the created runner with its generated `$id`. That id is what you
run against below.
</Step>

<Step>
## Provide the source

If `sourceType` is `git`, the worker clones `sourceUrl` at `branch` for each run.
For a private repository, see the GitHub App connection in [Sites](/deploy/sites).

If `sourceType` is `upload`, push a gzipped tar or zip of your project to the
runner. This shares the deploy module's storage, and the archive is capped at
512 MB.

```bash
curl -X POST https://api.applad.io/v1/tests/runners/<runnerId>/source \
  -H "x-applad-key: <apiKey>" \
  --data-binary @project.tar.gz
```
</Step>

<Step>
## The report is the contract

Your `command` must leave a JUnit XML file at `reportPath`. Applad reads the
union of what runners actually emit: a bare `<testsuite>` or a `<testsuites>`
wrapper, nested suites, failures as elements or attributes, and time in seconds.
Each `<testcase>` becomes one recorded case:

- an `<error>` marks the case **errored** (the framework failed to run it),
- a `<failure>` marks it **failed** (the test disagreed with the code),
- a `<skipped>` marks it **skipped**,
- anything else is **passed**.

Configure your framework to emit JUnit. For example, Playwright:

```ts
// playwright.config.ts
export default {
  reporter: [['junit', { outputFile: 'junit.xml' }]],
};
```
</Step>

<Step>
## Trigger a run

Trigger a run of the runner. You can pass a `target` (the URL the tests run
against, exposed to the container as the `BASE_URL` environment variable) and a
`suiteId` to narrow which tests execute.

```bash
curl -X POST https://api.applad.io/v1/tests/runners/<runnerId>/run \
  -H "x-applad-key: <apiKey>" \
  -H "Content-Type: application/json" \
  -d '{ "triggerType": "manual", "target": "https://staging.example.com" }'
```

The response is a run with `status: "queued"`. Poll it, or watch the live log
stream while it runs:

```bash
curl https://api.applad.io/v1/tests/runs/<runId> -H "x-applad-key: <apiKey>"
curl https://api.applad.io/v1/tests/runs/<runId>/stream -H "x-applad-key: <apiKey>"
```
</Step>

<Step>
## Read the results

A finished run carries the verdict and the tallies:

```json
{
  "$id": "run_...",
  "status": "passed",
  "target": "container",
  "targetUrl": "https://staging.example.com",
  "triggerType": "manual",
  "total": 42, "passed": 40, "failed": 0, "skipped": 2,
  "flaky": 1, "quarantined": 0,
  "durationMs": 18320
}
```

`status` is `passed`, `failed` (a blocking case failed), or `errored` (the run
itself could not complete). List the individual cases, failures and errors
first:

```bash
curl https://api.applad.io/v1/tests/runs/<runId>/cases -H "x-applad-key: <apiKey>"
```

```json
{
  "total": 42,
  "cases": [
    {
      "$id": "case_...",
      "suiteName": "checkout",
      "name": "applies a discount code",
      "status": "failed",
      "durationMs": 512,
      "failureMessage": "expected 90, received 100",
      "failureDetails": "at checkout.spec.ts:44"
    }
  ]
}
```

List past runs with `GET /v1/tests/runs` (optionally `?runnerId=<id>&limit=<n>`,
newest first).
</Step>

</Steps>
